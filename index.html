GET /principles how I approach engineering

Understand the failure first

I reproduce a problem before changing the code. Logs, inputs and edge cases usually tell you more than guessing at a fix.

Know what happens underneath

I like understanding how software interacts with operating systems, networks and other services instead of treating each layer as a black box.

Build for the next failure

Tests, useful logs, validation and clear error handling make the next production issue faster to find and safer to fix.
